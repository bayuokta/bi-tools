# AGENTS.md - Tooling Metadata Power BI

Repo ini berisi tooling untuk membuat workbook metadata dari project Power BI, dalam bentuk web lokal (server Python di `127.0.0.1`) dan perintah baris.
Project Power BI (PBIP, TMDL, PBIR) ada di repo terpisah: `..\..\Power BI\<project PBIP>`.

## Aturan arsitektur

- **Dilarang memakai metode HTTP `DELETE` pada API apa pun** (Power BI, Fabric, maupun API lokal). Operasi hapus/bersihkan memakai `POST` (`/api/tsd/cache/clear`, `/api/jobs/{id}/cancel`). `Transport.request` menolak `DELETE` sebelum request dikirim, dan `tests\test_architecture.py` menjaga tidak ada pemakaian `DELETE`/`requests.delete(`. Larangan ini khusus metode HTTP; `DELETE FROM` pada SQLite lokal tetap boleh untuk pemeliharaan tabel.
- `core\` tidak boleh memakai `print`, `input`, `argparse`, atau `SystemExit`. Lapor progres lewat parameter `log`, dan kesalahan lewat `ExtractionError`.
- `core\` tidak boleh mengimpor FastAPI/uvicorn atau PySide6; `server\` tidak boleh mengimpor `app\`; `cli\` tidak boleh mengimpor `server\`.
- `core\requests.py` adalah satu sumber pemetaan input: cakupan (`SCOPE_*`/`split_scope`), validasi GUID/endpoint/path, dan `CaptureOptions`. Web/CLI tidak menyusun `CaptureOptions` atau `extract_report`/`extract_model` sendiri.
- `cli\` dan `server\` hanya merangkai input dan menampilkan hasil; logika ekstraksi tetap di `core\`.
- Nomor versi hanya ditulis di `core\version.py`. Tag rilis `vX.Y.Z` wajib sama dengan nilai itu; jangan menulis nomor versi di spec, ISS, workflow, atau dokumentasi perintah.
- Wheel `bitools_sync` diterbitkan sebagai aset rilis oleh `.github\workflows\release.yml` dan dipasang notebook lewat `%pip install <url>`; jangan menambah jalur distribusi lain tanpa alasan. Notebook Fabric memakai kredensial SP di cell (workspace tanpa Git integration) — karena itu jangan mengaktifkan Git integration untuk workspace notebook, dan rotasi secret 6 bulan.
- Fabric `updateDefinition` (model/report) selesai tanpa payload hasil; jangan memanggil `/operations/{id}/result` untuk update. `_poll_operation(expect_result=False)` dipakai khusus update, sedangkan create tetap memakai result untuk mendapatkan ID item.
- Upload snapshot hanya di `sync\graph.py` (Graph app-only, `Sites.Selected`). Jangan menaruh upload di aplikasi web: aplikasi hanya mengunduh snapshot dari folder SharePoint/OneDrive yang tersinkron. Snapshot diunggah sebagai `bi_tools_snapshot.db` lalu `.sha256`; upload session dipakai untuk file >10 MiB. `tests\test_architecture.py` menjaga `graph.microsoft.com` hanya ada di `sync/`.
- Paket executable wajib **onedir**. `core\paths.py` menentukan folder aplikasi dari folder `.exe`, sedangkan `core\tsd.py` (template), `core\xmla_client.py` (DLL ADOMD), dan `core\best_practice.py` (katalog aturan) mencari aset di `ROOT`; karena itu `packaging\bi_tools.spec` menyalin `templates\`, `libs\`, `web\`, dan `rules\` ke samping exe setelah `COLLECT`, bukan lewat `datas` yang berakhir di `_internal`. Jangan mengubah ke onefile tanpa menyesuaikan `core\paths.py`.
- Satu paket berisi tiga executable: `BI Tools.exe` (server web, console), `bi-tools-cli.exe`, dan `bi-tools-sync.exe` (program sync). GUI PySide6/`app\` sudah dihapus di 0.4.0; jangan menambahkan kembali exe klasik atau PySide6 ke spec/requirements. Permukaan CLI paket adalah `cli\__main__.py`; perintah baru wajib didaftarkan di `COMMANDS` dan modulnya tetap menyediakan `main(argv)`.
- `bi-tools-cli install-browser` memanggil driver Playwright bawaan (`playwright.__main__`), bukan `python -m playwright`, karena paket tidak menyertakan interpreter. Tanpa argumen perintah ini berarti `install chromium` (argumen lain diteruskan apa adanya). Chromium (±150 MB) tidak dibundel; installer menawarkan task unduhan, dan capture pertama mengunduh otomatis lewat driver Playwright (`core\pbi_capture\browsers.py::install_chromium`) kecuali dimatikan dengan `CaptureOptions.auto_install_browser=False`/`--no-auto-install-browser`/checkbox web. Pesan `CaptureError` saat unduhan gagal tetap menyebut `bi-tools-cli install-browser` (bukan hanya `pip`).
- Playwright memaksa `PLAYWRIGHT_BROWSERS_PATH=0` untuk proses driver saat `sys.frozen`, sehingga browser dicari di `playwright/driver/package/.local-browsers` (di dalam `_internal`). `browsers.prepare_environment()` menimpanya ke `%LOCALAPPDATA%\ms-playwright` sebelum `sync_playwright()` dan sebelum installer, agar unduhan dan launch menunjuk folder yang sama dan bertahan saat aplikasi di-upgrade. Jangan menghapus panggilan itu atau menggantinya dengan path di dalam folder aplikasi tanpa alasan kuat.
- ZIP portable yang diunduh dari GitHub membawa **Mark of the Web** (`Zone.Identifier`) pada hampir semua berkas. .NET Framework menolak `Assembly.LoadFrom` untuk assembly bertanda itu (HRESULT `0x80131515`) dan pythonnet hanya melaporkan `Failed to resolve Python.Runtime.Loader.Initialize`. `core\xmla_client.py` membuka blokir `Python.Runtime.dll` + ADOMD otomatis (`unblock_file`/`unblock_dotnet_assemblies`) sebelum `import clr`; bila folder read-only, `XmlaError` menyebut `Get-ChildItem -Recurse | Unblock-File` dan saran installer. Installer tidak terkena karena Inno Setup membuat berkas baru. Jangan menggantinya dengan `loadFromRemoteSources` (melemahkan sandbox .NET seluruh proses).
- Installer Inno Setup memasang per pengguna (`{autopf}` = `%LOCALAPPDATA%\Programs`) supaya tanpa UAC dan folder aplikasi bisa ditulis. Opsi all-users tetap ada dan mengandalkan fallback `%LOCALAPPDATA%\BI Tools` di `core\paths.py`. Jangan menambahkan `[UninstallDelete]` untuk `outputs\`/`data\`, dan jangan membundel `outputs\`, `data\`, `.pbix`, `.env`, atau `TSD_assets\` (ISS memakai `Excludes`, ZIP memakai filter). `packaging\build.ps1` memakai `BI_TOOLS_ISCC` bila ISCC tidak ada di lokasi standar.
- Rilis hanya diterbitkan dari tag `vX.Y.Z` (`.github\workflows\release.yml`); `workflow_dispatch` hanya menghasilkan artefak. Artefak: `BITools-Setup-<versi>.exe`, `BITools-<versi>-portable.zip`, `bitools_sync-<versi>-py3-none-any.whl`, `SHA256SUMS.txt`. Paket belum ditandatangani digital, jadi peringatan SmartScreen adalah perilaku yang diketahui.
- Catatan rilis GitHub disusun workflow dari bagian `CHANGELOG.md` yang judulnya memuat nomor versi (`## <tanggal> - Rilis X.Y.Z`), ditambah daftar aset, catatan upgrade, dan checksum; `--notes` ditempel di atas catatan commit otomatis (`--generate-notes`). Jangan menulis ulang catatan rilis di workflow atau membuat file catatan terpisah: ganti `## Belum dirilis` menjadi judul bertanggal saat menaikkan versi, karena workflow gagal bila bagian versi tidak ditemukan.
- Action GitHub minimal yang dipakai adalah versi Node.js 24 (`actions/checkout@v7`, `actions/setup-python@v7`, `actions/upload-artifact@v6`); jangan turunkan ke `checkout@v4`/`setup-python@v5`/`upload-artifact@v4` karena memunculkan anotasi deprecation Node.js 20.
- `outputs\` dan `data\` tetap dibuat saat runtime, bukan oleh installer; `packaging\build.ps1` dan workflow tidak boleh membuatnya di `dist\`.
- Lokasi runtime hanya di `core\paths.py`: `APP_DIR` (folder executable saat `sys.frozen`, root repo saat dijalankan sebagai skrip), `OUTPUTS_DIR`, `outputs_dir()`, `data_dir()`. Semua default hasil generate (report, model, TSD, ekspor analisa, CLI tanpa `--out`) memakai `outputs\`; folder tidak dibuat saat import, hanya di jalur tulis. Bila folder aplikasi read-only (mis. Program Files), `outputs_dir()`/`data_dir()` jatuh ke `%LOCALAPPDATA%\BI Tools`. `core\pbix.ROOT` = `APP_DIR`, sehingga `DEFAULT_PBIX`, `templates\`, dan `data\` ikut executable.

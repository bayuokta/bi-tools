# AGENTS.md - Tooling Metadata Power BI

Repo ini berisi tooling untuk membuat workbook metadata dari project Power BI, dalam bentuk web lokal (server Python di `127.0.0.1`) dan perintah baris.
Project Power BI (PBIP, TMDL, PBIR) ada di repo terpisah: `..\..\Power BI\<project PBIP>`.

## Urutan baca yang disarankan

1. `README.md` untuk cara pakai dan struktur.
2. Fungsi yang relevan di modul terkait (gunakan grep, jangan baca seluruh file besar).
3. Workbook `.xlsx` hanya jika butuh angka hasil; gunakan `pandas.read_excel` per sheet.

Jangan membuka file JSON di project PBI (`Report/definition/**`, `SemanticModel/definition/**`) untuk mencari data; gunakan script atau workbook hasilnya.

## Perintah

```powershell
python -m server                                # server web lokal + buka browser
python -m server --no-browser --port 8800       # server tanpa membuka browser
python extract_report_metadata.py --report "<file>.pbix"          # report, tanpa Desktop
python extract_report_metadata.py --report-url "https://app.powerbi.com/groups/<ws>/reports/<id>"  # report dari Power BI Service
python extract_report_metadata.py --workspace-id <ws> --report-id <id>                              # service principal dari .env
python extract_model_metadata.py --report "<file>.pbix"           # model, Desktop harus terbuka (satu instance)
python extract_model_metadata.py --no-report                      # model tanpa kolom usage report
python extract_model_metadata.py --list-instances  # daftar instance Power BI Desktop
python extract_tsd.py                           # TSD dari workbook di folder tooling
python extract_tsd.py --final --expand-all      # dokumen final, semua panel expand terbuka
python verify_reference.py --pbix "<file>.pbix"                   # bandingkan report + model dengan angka acuan
python verify_reference.py --pbix "<file>.pbix" --no-model         # verifikasi report saja
python extract_lineage.py --stats               # statistik database lineage
python extract_lineage.py --search "Contoh"    # cari item di database lineage
python extract_lineage.py --check               # diagnostik edge dan riwayat scan
python extract_lineage.py --scan                # scan REST API (butuh kredensial di .env/environment)
python extract_lineage.py --sync-workspaces     # daftar workspace ke SQLite (1-2 request)
python analyze_semantic_model.py --workspace-id <ws> --dataset-id <ds>              # ukuran + pemakaian kolom
```

## Aturan arsitektur

- `core\` tidak boleh memakai `print`, `input`, `argparse`, atau `SystemExit`. Lapor progres lewat parameter `log`, dan kesalahan lewat `ExtractionError`.
- `core\` tidak boleh mengimpor FastAPI/uvicorn atau PySide6; `server\` tidak boleh mengimpor `app\`; `cli\` tidak boleh mengimpor `server\`.
- `core\requests.py` adalah satu sumber pemetaan input: cakupan (`SCOPE_*`/`split_scope`), validasi GUID/endpoint/path, dan `CaptureOptions`. Web/CLI tidak menyusun `CaptureOptions` atau `extract_report`/`extract_model` sendiri.
- `cli\` dan `server\` hanya merangkai input dan menampilkan hasil; logika ekstraksi tetap di `core\`.
- Nomor versi hanya ditulis di `core\version.py`. Tag rilis `vX.Y.Z` wajib sama dengan nilai itu; jangan menulis nomor versi di spec, ISS, workflow, atau dokumentasi perintah.
- Paket executable wajib **onedir**. `core\paths.py` menentukan folder aplikasi dari folder `.exe`, sedangkan `core\tsd.py` (template) dan `core\xmla_client.py` (DLL ADOMD) mencari aset di `ROOT`; karena itu `packaging\bi_tools.spec` menyalin `templates\`, `libs\`, dan `web\` ke samping exe setelah `COLLECT`, bukan lewat `datas` yang berakhir di `_internal`. Jangan mengubah ke onefile tanpa menyesuaikan `core\paths.py`.
- Satu paket berisi dua executable: `BI Tools.exe` (server web, console) dan `bi-tools-cli.exe` (console). GUI PySide6/`app\` sudah dihapus di 0.4.0; jangan menambahkan kembali exe klasik atau PySide6 ke spec/requirements. Permukaan CLI paket adalah `cli\__main__.py`; perintah baru wajib didaftarkan di `COMMANDS` dan modulnya tetap menyediakan `main(argv)`.
- `bi-tools-cli install-browser` memanggil driver Playwright bawaan (`playwright.__main__`), bukan `python -m playwright`, karena paket tidak menyertakan interpreter. Tanpa argumen perintah ini berarti `install chromium` (argumen lain diteruskan apa adanya). Chromium (±150 MB) tidak dibundel; installer menawarkan task unduhan, dan capture pertama mengunduh otomatis lewat driver Playwright (`core\pbi_capture\browsers.py::install_chromium`) kecuali dimatikan dengan `CaptureOptions.auto_install_browser=False`/`--no-auto-install-browser`/checkbox web. Pesan `CaptureError` saat unduhan gagal tetap menyebut `bi-tools-cli install-browser` (bukan hanya `pip`).
- Playwright memaksa `PLAYWRIGHT_BROWSERS_PATH=0` untuk proses driver saat `sys.frozen`, sehingga browser dicari di `playwright/driver/package/.local-browsers` (di dalam `_internal`). `browsers.prepare_environment()` menimpanya ke `%LOCALAPPDATA%\ms-playwright` sebelum `sync_playwright()` dan sebelum installer, agar unduhan dan launch menunjuk folder yang sama dan bertahan saat aplikasi di-upgrade. Jangan menghapus panggilan itu atau menggantinya dengan path di dalam folder aplikasi tanpa alasan kuat.
- ZIP portable yang diunduh dari GitHub membawa **Mark of the Web** (`Zone.Identifier`) pada hampir semua berkas. .NET Framework menolak `Assembly.LoadFrom` untuk assembly bertanda itu (HRESULT `0x80131515`) dan pythonnet hanya melaporkan `Failed to resolve Python.Runtime.Loader.Initialize`. `core\xmla_client.py` membuka blokir `Python.Runtime.dll` + ADOMD otomatis (`unblock_file`/`unblock_dotnet_assemblies`) sebelum `import clr`; bila folder read-only, `XmlaError` menyebut `Get-ChildItem -Recurse | Unblock-File` dan saran installer. Installer tidak terkena karena Inno Setup membuat berkas baru. Jangan menggantinya dengan `loadFromRemoteSources` (melemahkan sandbox .NET seluruh proses).
- Installer Inno Setup memasang per pengguna (`{autopf}` = `%LOCALAPPDATA%\Programs`) supaya tanpa UAC dan folder aplikasi bisa ditulis. Opsi all-users tetap ada dan mengandalkan fallback `%LOCALAPPDATA%\BI Tools` di `core\paths.py`. Jangan menambahkan `[UninstallDelete]` untuk `outputs\`/`data\`, dan jangan membundel `outputs\`, `data\`, `.pbix`, `.env`, atau `TSD_assets\` (ISS memakai `Excludes`, ZIP memakai filter). `packaging\build.ps1` memakai `BI_TOOLS_ISCC` bila ISCC tidak ada di lokasi standar.
- Rilis hanya diterbitkan dari tag `vX.Y.Z` (`.github\workflows\release.yml`); `workflow_dispatch` hanya menghasilkan artefak. Artefak: `BITools-Setup-<versi>.exe`, `BITools-<versi>-portable.zip`, `SHA256SUMS.txt`. Paket belum ditandatangani digital, jadi peringatan SmartScreen adalah perilaku yang diketahui.
- Catatan rilis GitHub disusun workflow dari bagian `CHANGELOG.md` yang judulnya memuat nomor versi (`## <tanggal> - Rilis X.Y.Z`), ditambah daftar aset, catatan upgrade, dan checksum; `--notes` ditempel di atas catatan commit otomatis (`--generate-notes`). Jangan menulis ulang catatan rilis di workflow atau membuat file catatan terpisah: ganti `## Belum dirilis` menjadi judul bertanggal saat menaikkan versi, karena workflow gagal bila bagian versi tidak ditemukan.
- Action GitHub minimal yang dipakai adalah versi Node.js 24 (`actions/checkout@v7`, `actions/setup-python@v7`, `actions/upload-artifact@v6`); jangan turunkan ke `checkout@v4`/`setup-python@v5`/`upload-artifact@v4` karena memunculkan anotasi deprecation Node.js 20.
- `outputs\` dan `data\` tetap dibuat saat runtime, bukan oleh installer; `packaging\build.ps1` dan workflow tidak boleh membuatnya di `dist\`.
- Lokasi runtime hanya di `core\paths.py`: `APP_DIR` (folder executable saat `sys.frozen`, root repo saat dijalankan sebagai skrip), `OUTPUTS_DIR`, `outputs_dir()`, `data_dir()`. Semua default hasil generate (report, model, TSD, ekspor analisa, CLI tanpa `--out`) memakai `outputs\`; folder tidak dibuat saat import, hanya di jalur tulis. Bila folder aplikasi read-only (mis. Program Files), `outputs_dir()`/`data_dir()` jatuh ke `%LOCALAPPDATA%\BI Tools`. `core\pbix.ROOT` = `APP_DIR`, sehingga `DEFAULT_PBIX`, `templates\`, dan `data\` ikut executable.
- Setiap server start mengosongkan pilihan sesi lewat `SettingsStore.reset_session()` (workspace/report Service, workspace/report TSD, workspace/dataset analisa, instance Desktop). Preferensi tetap: kredensial/RLS, path database, cakupan ekstraksi, filter & sort analisa, opsi render TSD, dan folder output. Jangan menyimpan pilihan sesi di kunci baru tanpa menambahkannya ke `SESSION_SELECTION_KEYS`.
- Field `.pbix` halaman Ekstraksi mulai kosong dan tombol Jalankan nonaktif sampai file dipilih; `DEFAULT_PBIX` hanya fallback CLI/core, bukan prefill web. Folder output tidak mengikuti folder `.pbix`.
- Pekerjaan web dijalankan lewat `server\jobs.py::JobManager` (satu job, SSE, pembatalan). Handler API tidak boleh menjalankan ekstraksi/capture/XMLA langsung di event loop.
- Halaman Ekstraksi memakai urutan section yang sama: Cakupan ekstraksi, Semantic model, Sumber report, Output. Halaman Local hanya memakai instance Power BI Desktop; halaman Service hanya memakai endpoint XMLA + catalog. Jangan menambahkan instance di Service atau endpoint di Local.
- Halaman **Extraction & TSD** adalah satu alur dua langkah: `#view-ekstraksi` (langkah 1) dan `#view-tsd` (langkah 2) tampil inline di halaman yang sama. Tidak ada item sidebar terpisah untuk TSD; `showView("ekstraksi")` menampilkan langkah 2 bila `tsdUnlocked()`. Stepper `#metaSteps`/`#tsdLock` mengatur status, dan langkah 2 terbuka bila ekstraksi sukses **atau** `checklist.report` sudah ada. `setMetaStep()` menggulir ke langkah tujuan; jangan mengembalikan navigasi `data-view="tsd"` atau `showView("tsd")`.
- Instance Power BI Desktop hanya dibaca untuk halaman Local lewat satu job `list_instances` (`presenters.metadata.instances`). Jangan membaca instance dari halaman Service atau dari beberapa tempat. Input model aktif selama cakupan menyertakan model dan dinonaktifkan bila file yang dipilih adalah live connection (tanpa model lokal).
- Deteksi jenis `.pbix` dilakukan di `core\pbix.py` (`detect_pbix_source`), bukan di web: `DataModel` berarti model lokal; tanpa `DataModel` dengan koneksi `pbiServiceLive` berarti live connection. `RemoteArtifacts` saja bukan penanda live.
- Model lokal: ekstrak model via XMLA lebih dulu, lalu report divalidasi dengan workbook model yang baru dibuat. Live connection: report saja; validasi memakai workbook model yang ada bila tersedia.
- Cakupan ekstraksi (`extract_report`/`extract_model` di `core\jobs.py`) menentukan file yang dibuat. `Semantic model saja` tidak boleh menyentuh `Report_Metadata.xlsx`, dan `Report saja` tidak boleh memanggil XMLA. Minimal satu cakupan harus berjalan; bila tidak ada yang bisa diekstrak, job melempar `ExtractionError`.
- Grup Cakupan ekstraksi tidak punya centang validasi/usage. Web selalu mengirim `validate_with_existing=True` dan `include_report_usage` sesuai kemampuan sumber (PBIR tersedia untuk Local, cakupan report+model untuk Service). Jangan menambahkan kembali checkbox opt-out tanpa keputusan eksplisit.
- Kegagalan ekstraksi model tidak membatalkan report: report tetap dibuat tanpa validasi dan penyebabnya dicatat di log. Sebaliknya, bila cakupan hanya model dan model gagal, job tidak boleh menghasilkan file apa pun secara diam-diam.
- Workbook validasi dicari oleh `resolve_validation_model`/`find_validation_workbook`: workbook eksplisit (hasil ekstraksi model baru) -> folder output -> `outputs\` -> folder aplikasi. Deskripsi sumber di log menyertakan waktu modifikasi agar workbook usang terlihat. Jangan menambal path workbook langsung di web.
- Pilihan cakupan disimpan per sub-tab: `extraction/scope_local` dan `extraction/scope_service`. Bila kunci baru kosong, nilai lama `extraction/scope` dipakai sekali; jangan menyimpannya di file konfigurasi lain.
- Report Power BI Service memakai Fabric API `getDefinition`; seluruh logika HTTP, long running operation (`202` + `Location` + `Retry-After`), retry `429`, decode `InlineBase64`, dan materialisasi PBIR berada di `core\fabric_api.py`. Auth berada di `core\auth.py`; web dan CLI tidak boleh menyusun request sendiri.
- Satu `ServicePrincipal` dipakai semua jalur. Fabric API memakai scope `https://api.fabric.microsoft.com/.default`; Power BI REST, embed/Scanner, dan XMLA memakai `https://analysis.windows.net/powerbi/api/.default`. Token Power BI yang sama dipakai ulang untuk ADOMD (`AccessToken` + `OnAccessTokenExpired`), jadi tidak ada login kedua. Token hanya di memori proses: jangan tulis ke `data\settings.json`, database, log, cache, atau HTML.
- Login pengguna/browser sudah dihapus; jangan menambahkan kembali `azure-identity` atau mode login kedua tanpa keputusan eksplisit. `core\auth.py` tidak boleh mengimpor pythonnet/.NET; objek token ADOMD dibangun di `core\xmla_client.py`.
- Semua HTTP REST wajib lewat `core\api\transport.py` (retry, LRO, pagination, `ApiError`). Client per produk hanya menyusun path dan memetakan respons. Jangan memakai `Password=<token>` di connection string XMLA; token dipasang lewat `AccessToken`.
- Endpoint XMLA `powerbi://`/`asazure://` dirapikan oleh `normalize_powerbi_endpoint` (workspace di-encode, `?readonly` ditambahkan bila belum ada). Instance Desktop lokal tidak boleh diberi token.
- Report dari service wajib berformat PBIR. Report PBIR-Legacy (`report.json` tunggal) ditolak dengan `ExtractionError` dan saran simpan ulang sebagai PBIR; jangan menambahkan parser legacy diam-diam.
- Sumber Power BI Service mendukung ketiga cakupan: report lewat Fabric API, model lewat XMLA. Di halaman Ekstraksi, workspace dipilih dari katalog SQLite dan endpoint XMLA **diturunkan** dari nama workspace (`workspace_endpoint`), bukan diketik; catalog diambil dari daftar dataset workspace (`datasets_in_group`). `core\jobs.py` masih menerima `port` + `catalog` untuk pemanggil CLI/uji. Jangan mencampur Report getDefinition dengan XMLA dalam satu panggilan API; keduanya jalur berbeda di `_run_service_metadata_job`.
- Picker sub-tab Service: `workspace_options` (SQLite) mengisi combo workspace; dataset dimuat hanya bila cakupan menyertakan model, report hanya bila menyertakan report. Pemuatan lewat `presenters.metadata.workspace_contents` (sinkron di thread request, 1-2 panggilan REST) dan dipicu saat workspace dipilih atau cakupan berubah. Jangan memanggil REST API langsung dari `web\app.js`.
- Pilihan workspace/report hanya berlaku per sesi: `extraction/service_workspace_id` dan `extraction/service_report_id` dikosongkan `SettingsStore.reset_session()` setiap server start, jadi combo mulai kosong. Kunci lama `extraction/service_url` tidak dipakai lagi; tidak ada field URL report di UI.
- Pilih report otomatis mengisi catalog dari `report.datasetId`. Bila dataset tidak ada di workspace itu (dataset bersama di workspace lain), tampilkan peringatan dan biarkan catalog kosong; jangan menebak workspace lain. Report `PaginatedReport` ditolak saat `prepare()` karena ekstraksi butuh PBIR.
- Bila pemuatan daftar gagal (mis. kredensial belum lengkap), pilihan workspace dikembalikan ke keadaan sebelumnya (snapshot), bukan dibiarkan tidak sinkron dengan daftar.
- Sinkronisasi dijalankan dari halaman Pengaturan: `presenters.settings.sync_catalog` (job `run_workspace_sync`) dan `presenters.settings.run_scan` (job `run_lineage_scan`), keduanya memakai database yang **sudah disimpan** (`paths/lineage_db`), bukan nilai formulir yang belum disimpan. Mode dipakai bersama dan disimpan di `catalog/mode` (`auto`/`admin`/`member`); `Full scan` hanya untuk lineage (tidak mengubah hasil mode member). Status dihitung dari `workspace_status` + `database_summary` (workspace siap dipilih, sync katalog terakhir, scan lineage terakhir). Halaman Ekstraksi membaca ulang katalog saat dibuka dan halaman Lineage membaca status saat dibuka, jadi hasil sync langsung terlihat tanpa restart.
- Usage report untuk model dari service memakai folder definition hasil `getDefinition` (`run_model(report_definition=...)`), bukan file `.pbix`. Bila cakupan hanya model, usage tidak tersedia. CLI report service tetap report-only.
- Agregasi level visual (PBIR `Aggregation`, mis. `Min(TabelA.Kolom1)`) adalah implicit measure: `scan_report_usage` mencatatnya sebagai pemakaian kolom model lewat `Expression.Column` dan menyimpan fungsinya, bukan membuat objek/tabel baru dari `queryRef`. `12_Model_vs_Report` memberi catatan `Dipakai visual lewat agregasi: …`; `queryRef` berbentuk `Func(...)` tidak boleh dipecah menjadi tabel/kolom.
- URL/ID report divalidasi sebagai GUID di `core\fabric_api.py` (`ServiceReportRef.from_ids`, `parse_report_url`), bukan di web. URL `groups/me` ditolak.
- Kunci lama GUI (`extraction/active_tab`, `extraction/report_source`, `extraction/fabric_auth`) tidak dipakai lagi oleh web; jangan menghidupkannya kembali. Halaman aktif di web adalah state browser, bukan preferensi tersimpan.
- Uji Fabric/transport tidak boleh melakukan network atau login: inject `requests.Session`, fungsi `sleep`, `msal_app`, dan client tiruan. Token diuji lewat `tests\test_api_transport.py`, `tests\test_xmla_auth.py`, dan `tests\test_architecture.py` (penjaga: `requests` hanya di `core\api\transport.py`, MSAL hanya di `core\auth.py`, tidak ada `Password=`).
- Pemilihan instance Power BI Desktop tidak boleh otomatis bila ada lebih dari satu instance (lihat `open_client` di `core\xmla_client.py`). `--port` tidak boleh memakai cadangan ke instance lain.

- `detect_ports` harus memeriksa workspace installer klasik dan Microsoft Store; jangan hanya salah satu. Listener `msmdsrv` tidak selalu berstatus `Listen`, jadi cari pemilik port lalu cocokkan nama prosesnya.

- Template TSD berasal dari repo `..\template-tsd` dan disalin apa adanya ke `templates\tsd.template.html`; jangan mengedit template di repo ini.
- `core\tsd.py` adalah satu-satunya tempat membaca workbook TSD, menyusun konteks Jinja, dan merender HTML. `cli\tsd.py` dan `server\presenters\tsd.py` hanya merangkai input; `web\app.js` hanya mengirim payload dan merender state (tidak boleh menyusun konteks TSD).
